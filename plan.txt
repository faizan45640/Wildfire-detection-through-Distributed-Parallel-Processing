PHASE 3 — Serial Version
Who does this: Person 2
File: serial/wildfire_serial.cpp
What it does
Reads the thermal grid, loops over every single pixel one by one, checks if temperature exceeds fire threshold (200°C), marks it as fire, counts total fire pixels, records coordinates.
Logic step by step
Step 1 — Read grid dimensions from file header
Step 2 — Allocate 2D array in memory
Step 3 — Load all temperature values from thermal_grid.bin
Step 4 — Start timer (use clock_gettime for precision)
Step 5 — Loop: for every row, for every column:

If temperature > 200 → mark as fire pixel
Store its row, column coordinates
Increment fire counter

Step 6 — Stop timer
Step 7 — Print:

Total pixels processed
Total fire pixels found
List of fire coordinates
Execution time in milliseconds

Step 8 — Save fire map to results/serial_firemap.bin
Compile command
bashg++ -o wildfire_serial serial/wildfire_serial.cpp
Run command
bash./wildfire_serial
Record this number
Write down the execution time. This is your baseline for speedup calculation.

PHASE 4 — OpenMP Parallel Version
Who does this: Person 3
File: parallel/wildfire_openmp.cpp
What it does
Same logic as serial but uses OpenMP to process multiple rows simultaneously using threads on one machine.
Logic step by step
Step 1 — Read grid (same as serial)
Step 2 — Start timer
Step 3 — Add OpenMP directive above the loop:
cpp#pragma omp parallel for reduction(+:fire_count) schedule(dynamic)
Step 4 — Same detection loop runs but now split across threads automatically
Step 5 — Use reduction clause to safely sum fire_count across threads (avoids race condition)
Step 6 — Use critical section when writing fire coordinates to shared list (avoids data corruption)
Step 7 — Stop timer
Step 8 — Print execution time + results
Compile command (important: add -fopenmp flag)
bashg++ -fopenmp -o wildfire_openmp parallel/wildfire_openmp.cpp
Run with different thread counts (for scalability)
bashOMP_NUM_THREADS=1 ./wildfire_openmp
OMP_NUM_THREADS=2 ./wildfire_openmp
OMP_NUM_THREADS=4 ./wildfire_openmp
OMP_NUM_THREADS=8 ./wildfire_openmp
Record all times
These give you your scalability table for the report.

PHASE 5 — MPI + OpenMP Combined Version
Who does this: All 4 together (main deliverable — pair up for debugging)
File: parallel/wildfire_parallel.cpp
What it does
MPI divides the grid across all 4 machines. Each machine runs one MPI process and uses OpenMP threads to process its chunk in parallel. Results sent back to master.
Logic step by step
Step 1 — Master (Machine 1) only:

Read full grid from file
Divide grid into equal row chunks (total rows ÷ number of MPI processes)
Example: 1000 rows, 4 processes → each gets 250 rows

Step 2 — MPI_Scatter:

Master sends each chunk to its respective process
Process 0 keeps chunk 0 (its own)
Process 1 on Machine 2 receives chunk 1
Process 2 on Machine 3 receives chunk 2
Process 3 on Machine 4 receives chunk 3

Step 3 — Each process independently:

Runs OpenMP parallel loop on its received chunk
Each thread checks pixels for fire threshold
Counts local fire pixels using reduction

Step 4 — MPI_Gather:

Each process sends its local fire count back to master
Each process sends its local fire map back to master

Step 5 — Master only:

Combines all fire maps into complete grid
Sums all fire counts
Stops timer
Prints total execution time + results

Step 6 — Save combined fire map
Compile command
bashmpicxx -fopenmp -o wildfire_parallel parallel/wildfire_parallel.cpp
Hostfile setup (do this when all 4 on same network or Tailscale)
bash# On Machine 1 (master), create hostfile

# Write inside (1 process per machine):

192.168.X.X slots=1 user=USER4    ← Machine 4 IP
Run command (from Machine 1, where dataset lives)

Step 2 — Calculate Speedup
Speedup = Serial Time / Parallel Time

Example:
Serial time    = 800ms
Parallel time  = 210ms
Speedup        = 800/210 = 3.8x
Step 3 — Calculate Efficiency
Efficiency = Speedup / Number of Processes × 100%

Example:
Efficiency = 3.8 / 4 × 100 = 95%
Step 4 — Plot graphs (write in results/plot_results.py)
